# Decision Log

Architectural and design decisions for `specr`. Newest first.

---

## 2026-03-20 — Reset dirty lockfiles before coordinator merge

**Decision:** In `coordinator_merge()`, before every merge attempt, run `git diff --name-only` and discard any dirty generated lockfiles with `git checkout -- <path>`.

**Context:** After resolving a Cargo.lock conflict via `cargo generate-lockfile`, the file is left modified in the main workdir. The next `git merge` then fails with `"Your local changes to Cargo.lock would be overwritten by merge"`.

**Why:** The dirty lockfile has no durable value — if the merge produces a fresh lockfile conflict, `resolve_lockfile()` regenerates it anyway. Discarding upfront is safe and unblocks the merge.

**Applies to:** `src/agent_runner/coordinator.rs` → `coordinator_merge()`

---

## 2026-03-20 — Regenerate lockfiles instead of LLM text-merging them

**Decision:** In `resolve_conflicts()`, handle known generated lockfiles (Cargo.lock, package-lock.json, yarn.lock, go.sum, etc.) with a dedicated regeneration pass before any LLM resolution.

**Context:** Cargo.lock conflicts were being sent to the LLM for text resolution, which produces nonsense — the file is deterministically generated by tooling.

**Why:** Running `cargo generate-lockfile` (or the equivalent for each ecosystem) produces a correct, consistent lockfile that reflects the merged dependency tree. LLM text merging cannot replicate this.

**Fallback:** Unknown lockfiles get `git checkout --theirs` to clear conflict markers.

**Applies to:** `src/agent_runner/coordinator.rs` → `resolve_conflicts()`, `is_generated_lockfile()`, `resolve_lockfile()`

## 2026-03-20 — Fix coordinator_merge conflict detection

**Decision:** Replace `git_command()` (which bails on non-zero) with a direct `TokioCommand` in `coordinator_merge`, then use `git diff --name-only --diff-filter=U` to detect actual conflicts.

**Context:** `git merge` exits 1 for both conflicts AND genuine errors. The word `CONFLICT` appears on stdout, but `git_command` only captures stderr in the error — so `contains("CONFLICT")` was always false. Every merge conflict was being treated as a fatal error instead of routing to LLM resolution.

**Why:** `--diff-filter=U` reliably lists unmerged files regardless of what git printed. If unmerged files exist → conflict path. If none → real error → propagate.

**Applies to:** `src/agent_runner/coordinator.rs` → `coordinator_merge()`

## 2026-03-19 — Workers must not checkout default branch inside worktrees

**Decision:** In `finalize_task_done()` and the iteration-limit failure path, skip `git checkout <default_branch>` when `ctx.skip_tasks_md == true` (parallel/worktree mode). Worker just returns `Ok(())`.

**Context:** Git refuses `git checkout master` inside a worktree when master is already checked out in the main workdir: `"fatal: 'master' is already used by worktree at '...'"`.

**Why:** In parallel mode, the coordinator owns the default branch and performs all merges from the main workdir. Workers only need to finish their task branch and signal completion. The coordinator fetches and merges the branch independently.

**Applies to:** `src/agent_runner/mod.rs` → `finalize_task_done()`, loop limit path

## 2026-03-19 — Per-agent instruction files (.specr/ directory)

**Decision:** Use a `.specr/` directory in the project root for per-agent instruction files: `coder.md`, `code-reviewer.md`, `qa-reviewer.md`, `style-reviewer.md`, `coordinator.md`. Global defaults at `~/.config/specr/instructions/`.

**Context:** All agent prompts were hardcoded. No way to say "always use rustls" or "don't fail style review for missing doc comments" without editing specr source.

**Why:** `.specr/` is co-located with the project (easy to discover), git-tracked (instructions evolve with the codebase), and per-agent (different reviewers have different criteria). Global + project layers allow shared defaults without per-project repetition.

**Per-task override:** `## Agent Instructions` section in task detail file. Content is appended to the coder prompt for that task only.

**Priority chain:** global (`~/.config/specr/instructions/`) → project (`.specr/`) → per-task. All additive.

**Applies to:** `src/instructions.rs`, all agent prompt builders

## 2026-03-19 — specr drift auto-detects base ref from last SPEC.md commit

**Decision:** When no `--base` flag is given, `specr drift` finds the last commit that touched `SPEC.md` via `git log -1 -- SPEC.md` and diffs against its parent (`<hash>^`).

**Context:** The previous default of `HEAD` produced an empty diff if spec changes were already committed, making `specr drift` silently useless after every commit.

**Why:** "The commit before the last time SPEC.md changed" is almost always what the user means. This works for both committed and uncommitted spec changes.

**Fallback chain:** `<last-spec-commit>^` → git empty tree (first commit) → `HEAD~1`.

**Applies to:** `src/task_generator/mod.rs` → `detect_spec_base()`

## 2026-03-19 — Parallel coordinator architecture

**Decision:** Coordinator stays on the default branch in the main workdir. Workers each get a `git worktree add` at `<worktree_base>/specr-worker-<task_id>`. Workers skip all TASKS.md writes. Coordinator serializes all merges, test runs, and TASKS.md updates.

**Context:** Sequential execution is a bottleneck on large projects (20+ tasks). Workers need filesystem isolation to avoid clobbering each other's changes.

**Why:** Git worktrees give each worker a fully independent filesystem view of the repo without cloning. The coordinator-as-serializer model avoids distributed write coordination — there is exactly one writer to master at any time.

**Semaphore:** `Arc<Semaphore>` caps concurrent workers at `config.agent.parallel_jobs`.

**Conflict resolution:** `resolve_conflicts = true` by default. LLM resolves conflict markers per-file; tests are the oracle (not subjective review).

**`skip_tasks_md: bool` in RunCtx:** Gates all TASKS.md reads/writes and the `git checkout <default>` in `finalize_task_done`. Workers set this to `true`.

**Applies to:** `src/agent_runner/coordinator.rs`, `src/agent_runner/mod.rs` (`RunCtx`)

## 2026-03-19 — specr drift command

**Decision:** `specr drift` generates tasks only for what changed in SPEC.md, appending to the existing TASKS.md rather than regenerating everything.

**Context:** After `specr tasks` is run and work begins, updating SPEC.md would previously require full task regeneration, discarding all `done`/`in-progress` state.

**Why:** Append-only preserves completed work. New tasks get IDs force-renumbered from `max_existing + 1` so they never collide. The LLM is instructed to return `[]` if no new tasks are needed. New tasks may declare dependencies on existing IDs.

**Applies to:** `src/task_generator/mod.rs` → `drift()`

## 2026-03-18 — Retry prompt includes "already committed" summary

**Decision:** On every review-loop retry, prepend a summary of what was already committed on the task branch (git log + diff stat vs default branch) to the agent prompt.

**Context:** On large tasks (10+ files), agents were redoing completed work on each retry because they had no awareness of what was already in git. This caused thrashing and exhausted the iteration limit.

**Why:** Explicit "already done" context lets the agent focus on gaps identified by the reviewers rather than re-implementing from scratch.

**`max_loop_iterations` default:** Bumped from 5 to 10.

**Applies to:** `src/agent_runner/coding_agent.rs` → `build_retry_prompt()`, `already_committed_summary()`

## 2026-03-18 — api-agent runner (direct Anthropic API, no claude binary)

**Decision:** Add an `api-agent` runner alongside `claude-code`. Uses Anthropic tool-use (function calling) loop with four tools: `read_file`, `write_file`, `edit_file`, `run_command`.

**Context:** `claude-code` runner requires the `claude` CLI binary installed and authenticated. Users with only an API key or OAuth token have no runner option.

**Why:** Direct API calls are more controllable (tool set is fixed, context is managed explicitly) and don't require external binary management.

**Context compaction:** At 150K input tokens, keeps original task + last 4 messages, summarizes the middle via LLM. Prevents runaway context growth on long tasks.

**`max_agent_turns` default:** 30 tool-call iterations per task.

**Applies to:** `src/agent_runner/api_agent.rs`

---

## 2026-03-18 — OAuth tokens require Claude Code identity system block

**Decision:** For OAuth tokens (`sk-ant-oat*`), the Anthropic API requires the system prompt to be a `Vec<ContentBlock>` with `{"type":"text","text":"You are Claude Code, Anthropic's official CLI for Claude."}` as the first block. Plain string system prompts return HTTP 400.

**Context:** Direct API calls with OAuth tokens were returning 400 errors. API-key calls worked fine.

**Why:** OAuth tokens are issued for Claude Code sessions; Anthropic validates that the session identity block is present.

**Applies to:** `src/llm/anthropic.rs` → `wrap_system_for_oauth()`

## 2026-03-18 — rustls-tls-native-roots for macOS TLS

**Decision:** Use `rustls-tls-native-roots` feature on reqwest instead of the bundled Mozilla CA roots.

**Context:** TLS handshakes to `api.anthropic.com` were failing on macOS while curl succeeded. The bundled Mozilla roots differ from the macOS Keychain/system roots.

**Why:** macOS corporate environments and VPN setups often inject custom CA certs into the system Keychain. `native-roots` uses those; bundled roots don't.

**Applies to:** `Cargo.toml` reqwest features

---

## 2026-03-18 — Separate filter functions for diff formats

**Decision:** Use `filter_name_status()` for `git diff --name-status` output (tab-separated `M\tfile`) and `filter_diff_paths()` for unified diff format. Do not mix them.

**Context:** `changed_files` uses `--name-status` format; passing it to `filter_diff_paths()` silently failed to strip TASKS.md, causing the "already done" check to never fire and reviewers seeing TASKS.md status changes as code.

**Applies to:** `src/agent_runner/mod.rs`

---

## 2026-03-18 — Review model can be separate from coding model

**Decision:** Add `review_model`, `review_provider`, and `review_api_key_env` config fields. Reviews run on a separate (optionally cheaper) model from the coding agent.

**Context:** Reviews use 3 parallel LLM calls on every iteration. Running them on `opus` is expensive; `haiku` or `sonnet` is sufficient for structured JSON review output.

**Why:** Decouples cost-optimisation for reviews from the quality requirements of the coding agent.

**Applies to:** `src/config.rs`, `src/agent_runner/mod.rs` → `RunCtx`

---

## 2026-03-18 — CoordCtx struct to satisfy clippy::too_many_arguments

**Decision:** Bundle coordinator-shared state (`config`, `llm`, `review_llm`, `notifier`, `workdir`, `spec_content`, `default_branch`, `test_cmd`) into `CoordCtx` with `Arc`/`Clone` derives.

**Context:** `run_parallel()` and `run_worker()` exceeded clippy's 7-argument limit.

**Why:** Struct is the idiomatic Rust solution. `Arc` on LLM clients + `Clone` on the struct gives workers ownership without cloning the underlying clients.

**Applies to:** `src/agent_runner/coordinator.rs`

## 2026-03-17 — Injectable I/O for testability

**Decision:** All interactive prompts use `reader: &mut R where R: BufRead` instead of reading directly from stdin. Tests pass a `Cursor<&[u8]>` with pre-set answers.

**Why:** Enables deterministic unit tests for the full spec-composer and task-generator pipelines without TTY interaction.

**Applies to:** `src/spec_composer/`, `src/task_generator/`

---

## 2026-03-17 — rustls only (no OpenSSL/native-tls)

**Decision:** All TLS via rustls. OpenSSL and native-tls are explicitly excluded from dependencies.

**Why:** Enables cross-compilation without OpenSSL build dependencies. Simpler CI/CD. Consistent behaviour across macOS/Linux.

**Applies to:** `Cargo.toml` (reqwest features)

---

## 2026-03-17 — TOML config at OS-standard path

**Decision:** Config at `~/Library/Application Support/specr/config.toml` on macOS (via `dirs::config_dir()`). Auto-created with defaults on first run. All secrets via env vars only — never written to config.

**Why:** Follows platform conventions. Keeps secrets out of files that might be synced or committed.

**Applies to:** `src/config.rs`

---

## 2026-03-17 — Task sizes: S/M/L with L blocked

**Decision:** L-sized tasks are never handed to an agent. `specr run` skips them with an explicit message. Use `specr split --task NNN` to decompose first.

**Why:** L tasks are too large for reliable single-agent execution. Forcing decomposition keeps each agent context small and reviewable.

**Applies to:** `src/agent_runner/resolver.rs`

---

## 2026-03-17 — Three-reviewer parallel review pipeline

**Decision:** Every completed task diff is reviewed simultaneously by three independent LLM calls: code review, QA review, style review. All receive only the filtered diff (TASKS.md excluded).

**Context:** Single-reviewer prompts produce inconsistent feedback. Parallel calls are faster than sequential.

**Why:** Separation of concerns: code correctness, test quality, and style are evaluated independently with tailored system prompts. Only `critical` findings block task completion; `warnings` and `suggestions` are logged.

**Applies to:** `src/agent_runner/review.rs`

---

## 2026-03-17 — git add -u (not git add -A) in agent prompts

**Decision:** Agent prompts instruct: `git add -u && git add <new-files> && git commit`. Never `git add -A`.

**Why:** `git add -A` in a worktree can accidentally stage files from sibling worktrees or the parent repo. `-u` stages only tracked modifications; new files are listed explicitly by the agent.

**Applies to:** All agent system prompts

---

## 2026-03-17 — spec-version tracking

**Decision:** SPEC.md and TASKS.md both carry a `spec-version` integer in their frontmatter. A mismatch indicates drift.

**Why:** Provides a reliable signal for "tasks are out of date relative to the spec" without diffing content. Incremented on every `specr refine`.

**Applies to:** `src/store.rs`, `src/spec_composer/`, `src/task_generator/`
